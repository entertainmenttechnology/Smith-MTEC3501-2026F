### 3. Presentation Deliverables Structure

David Smith walked through the required components of the presentation.

- **Details**
    - David Smith: Required deliverables include — 10-minute oral presentation, slide deck, annotated research bibliography, written speculative proposal, milestone and issue tracking, and a prototype plan.
    - David Smith: Recommended slide structure: project name and presenter name, project type and goals, research and precedents (inspirational and precedent), project breakdown (North Star vision vs. proof of concept vs. least viable product), milestones and feasibility, and estimated timeline.

### 4. GitHub Repository Setup and Workflow

David Smith demonstrated how to use GitHub for project management, including repositories, issues, labels, and project boards.

- **Details**
    - David Smith: Each student has their own repository this semester (changed from a shared repository used previously).
    - David Smith: Students should update their README with a project description and link to relevant documents.
    - David Smith: GitHub Issues should be created for each deliverable and research task, with appropriate labels (e.g., precedent research, technical research, documentation).
    - David Smith: A Kanban-style project board should be created within GitHub Projects to track issue status (Backlog, Ready, In Progress, In Review, Done).
    - David Smith: Sub-issues can be created under parent issues to break down larger tasks (e.g., slide deck broken into introduction, research and precedents, project breakdown).
    - David Smith: A gitignore file should be used to prevent large Unity or asset files from being pushed to the cloud repository.
    - David Smith: Source code should live in an /src directory following best practices.
    - A student: Confirmed seeing the Projects tab and successfully began setting up a project board during the session.
- **Conclusion**
    - Each student must have a GitHub repository with a populated README, issues for each presentation deliverable, and a Kanban project board.
    - Issue labels should reflect the type of work (research, documentation, technical, etc.).

### 6. Zotero Research Management

David Smith demonstrated how to use Zotero for organizing and generating research bibliographies.

- **Details**
    - David Smith: Each student must create their own sub-collection under the MTEC 3501 → Students folder in Zotero.
    - David Smith: Research should be tagged and organized by type: inspirational research, precedent research, technical research.
    - David Smith: The Zotero browser connector can be used to save web pages directly into a student's collection.
    - David Smith: Annotations (item notes) can be added to each Zotero entry to document findings and follow-up questions.
    - David Smith: Bibliographies can be auto-generated from Zotero in APA or other formats and pasted into Google Docs or GitHub.
    - David Smith: Students may drag items from others' Zotero collections into their own but should not remove items from others' collections.
    - David Smith: A research markdown document should be created in the GitHub repository and linked from the README.
- **Conclusion**
    - Each student must have a named Zotero sub-collection with research entries before the October 15th presentation.
    - Annotated bibliographies will be generated from Zotero and included in the presentation and GitHub repository.

### 7. Types of Research

David Smith outlined the four categories of research expected for the project.

- **Details**
    - David Smith: Inspirational research — things that motivated the student to pursue this project (games, films, books, shows, etc.).
    - David Smith: Precedent research — existing projects or products similar to the student's idea; used to differentiate the student's work.
    - David Smith: Technical research — how to build the project; hardware, software, libraries, tutorials, tools.
    - David Smith: Resource research — ethically usable materials (open-source assets, MIT-licensed content, etc.).
- **Conclusion**
    - All four research types should be represented in the Zotero collection and referenced in the presentation.

### 8. Speculative Proposal and Project Scoping

David Smith explained the transition from broad speculation to a specific, structured project proposal.

- **Details**
    - David Smith: Students must define three levels of their project — North Star (full vision), least viable product (end-of-4501 deliverable), and proof of concept (what will be demonstrated this semester).
    - David Smith: The speculative proposal should live in the GitHub repository under the Docs/Speculation folder, or be linked from the README if stored in Google Docs.
    - David Smith: Students must commit to a specific project direction, even if it will evolve — a marker must be placed.
    - David Smith: The proof of concept only needs to demonstrate basic competency (e.g., opening Unity and showing a simple element with an action).
- **Conclusion**
    - Students must articulate a specific project idea with three defined scope levels before the October 15th presentation.
    - The speculative proposal document must be accessible via the GitHub repository.
