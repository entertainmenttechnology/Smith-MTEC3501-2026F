## 1) GitHub Issues and Labels

- Create an Issue for each presentation deliverable and research task (e.g., precedent research, technical research, documentation).
- Apply a label describing the type of work, using the numbered SRDMPA-stage format (e.g., `02_research-precedent`, `02_research-technical`, `03_design`). These labels don't exist in your repository yet — create them yourself (future semesters will have them pre-loaded in the template).
- Large deliverables (e.g., the slide deck) can be broken into sub-issues — for example, a "Slide Deck" parent issue with sub-issues for introduction, research & precedents, and project breakdown.

## 2) GitHub Kanban Project Board

- Create a Project Board if you don't already have one, with columns: **Backlog, Ready, In Progress, In Review, Done**.
- Add your Issues to the board and place them in the correct column.

## 3) GitHub Discussions

- Enable Discussions in your repository if it isn't already enabled.
- Post at least one Discussion item this week — a real question, unknown, or problem you want peer feedback on.

## 4) README Update

- Update your repository's main README with a brief project description and links to your speculative proposal, your research document (Part 6 below), and your Zotero collection.

## 5) Repository Organization

- Keep source files in a `/src` directory.
- Add a `.gitignore` appropriate to your project — this matters especially for **Unity** or other large-asset workflows, so build artifacts and large binaries aren't pushed to the cloud repository.

## 6) Zotero and Research Document

- Create your personal Zotero sub-collection under the **MTEC 3501 → Students** folder in the shared group library.
- Organize research by type: **inspirational**, **precedent**, **technical** (a fourth type, **resource** research — ethically usable assets/materials — is also part of the overall research model).
- Create a research Markdown document in your repository summarizing or linking your Zotero sources, and link it from your README.

## 7) Speculative Proposal

- Begin or continue your detailed speculative proposal, and make sure it's stored in your repository or linked from your README.

## 8) Project Scope Preview

Presentations will define three scope levels for your project: **North Star Vision**, **Least Viable Product**, and **Proof of Concept**. You'll formally write these into your proposal in Week 5 — for now, just be aware this is coming.
