# Week 6 Activity: Create a GitHub Milestone

## Purpose

Use a repository milestone to group the Issues that support your Weeks 7–8 midterm expert-feedback presentation. This activity introduces the GitHub milestone feature before you develop a dated project timeline in Week 8.

A **GitHub milestone** groups related Issues and tracks their completion. It is not itself an Issue or a Kanban card. The Issues associated with the milestone are the work items you can place on your Project board.

> **Keep the terms distinct:** This activity creates a GitHub repository milestone. It does not create a `[MILESTONE]` Issue that represents a validated system state; that is a different planning technique used later in the course.

## Before You Begin

Have your presentation-related Issues ready in your repository. Examples include:

- Refine the Make It Specific document and define the PoC / LVP / NSV
- Organize and annotate research; generate the bibliography
- Prepare the presentation deck and user-experience visual
- Identify technologies, current competencies, and learning needs
- Prepare specific questions for expert feedback

You do not need to create new Issues if suitable ones already exist. Update or reuse them.

## Activity Steps

1. Open your individual project repository on GitHub.
2. Open **Issues**, then choose **Milestones** near the Issues search controls.
3. Select **New milestone**.
4. Use this title: **Midterm Expert-Feedback Presentation**.
5. Add a short description, such as: “Group and track the project work needed to explain the current direction and receive expert feedback during Weeks 7–8.”
6. Create the milestone. A due date is optional; do not add one for this activity. Week 8 will introduce Start Date and Target Date fields for planning work on the Project roadmap.
7. Assign the relevant Issues to the milestone. Open an Issue and select the new milestone in its **Milestone** field in the sidebar. If GitHub offers bulk editing in your Issues list, you may assign several Issues at once.
8. Open your GitHub Project board. Confirm that the Issues associated with the milestone are on the board and in columns that represent their current status. Add any missing Issues to the board.

For screenshots and GitHub's current interface details, see the official guide: [Creating and editing milestones for issues and pull requests](https://docs.github.com/en/issues/using-labels-and-milestones-to-track-work/creating-and-editing-milestones-for-issues-and-pull-requests).
